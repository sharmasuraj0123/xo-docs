<Lead>
  **Setup → Jobs** saves commands that run on the Space server's machine. A
  **Repeating** job runs on a schedule you choose in words; a **One time** job
  runs once at a time you pick, or whenever you click **Run now**. Each job keeps
  its recent results and a full log on this machine.
</Lead>

Open **Setup** and choose **Jobs** in the sidebar, or go to
`/space/#/setup/commands` (the address kept its earlier name). Opening the page
does not create or run anything.

![Setup Jobs with two one-time jobs and one repeating job, each with Run now, Results, Edit and Delete](/images/space/setup-commands.png)

**Your jobs** lists every saved job. Each row shows its name and a **Repeating**
or **One time** badge, the description, the command, the folder it runs in
(**Runs in**), its latest status in words with how long ago it ran, and its
schedule, such as **Every hour** or **Runs when you click Run now**. Below that,
**Latest result** shows the exit code and the end of the output.

## Create a job

![New job form with Repeating selected, Daily chosen, a November calendar and the next three runs](/images/space/setup-job-editor.png)

1. Click **New job**. The **New job** card opens above **Your jobs**.
2. Under **What kind of job is this?**, choose **Repeating** (runs again and
   again, on a schedule you choose) or **One time** (runs once on the day and
   time you pick, or whenever you click **Run now**).
3. Under **When should it run?**:
   - For **Repeating**, pick how often: **Every…** (a number of minutes, hours,
     days or seconds, with a first-run time), **Hourly** (at a minute past each
     hour), **Daily** (at a time each day) or **Weekly** (on one day each week at
     a time). Optionally pick a start date on the calendar; with no date, the
     job starts right away. Days with runs get a dot.
   - For **One time**, set the time and pick the day on the calendar. With no
     day picked, the job waits until you click **Run now**.
4. Check the green summary line and **Next runs** below the calendar, for
   example *Every day at 09:00. First run: Nov 25, 2026, 9:00 AM.* Times are in
   your browser's time zone.
5. Under **What should it run?**, fill in:
   - **Name**: up to 64 letters, numbers, spaces, dots, dashes or underscores.
   - **Description (optional)**.
   - **Command**: the program and its arguments, such as `git status --short`.
     It runs directly, without a shell, so `|`, `&&`, `;` and `>` are not
     allowed. For an argument that contains spaces, write a JSON list:
     `["git", "commit", "-m", "Two words"]`.
   - **Run in folder (optional)**: an absolute path on the Space machine. Leave
     it blank to use the server's own folder.
   - **Stop it if a run takes longer than**: a number with seconds, minutes or
     hours. A run still going at that point is stopped and marked **Timed out**.
6. Click **Save job**. **Cancel** or the **✕** button closes the card without
   saving. If something is wrong, the error appears in the card and nothing is
   saved.

Jobs run with the server's permissions and environment. Job definitions and
output can contain sensitive data, so keep secrets out of command arguments.

A repeating job keeps a fixed interval, so a daily time can move by an hour when
daylight saving starts or ends. Timed jobs run only while **Update activity
automatically** is on in **Setup → Intelligence layer**, and only while the
server is running. Missed runs are not replayed; the job moves on to its next
time.

## Run a job now

Click **Run now** on the job's row, in Setup or in **Inbox → Jobs**. This works
for both kinds of job, including when automatic runs are off. It does not move a
repeating job's next scheduled time. While a job runs, its row shows that it is
running and updates when the run finishes. A job cannot overlap itself, and all
jobs share the server's limit on how many run at once; a conflict message means
the run could not start.

## Read results and history

Click **Results** on a job to open **Command results**: its newest **20 runs**,
newest first. Each run shows its status and duration, start and finish times,
whether it was manual or scheduled, the exit code, and the end of its output.
While the job is running, results update on their own.

![Command results with the command, its folder, the full log path with Copy log path, and one run](/images/space/setup-command-runs.png)

**Full log on this machine** shows where the complete output is kept, with a
**Copy log path** button. With the default Space data folder, the files are:

```text
~/.quirq/logs/scheduler/<job-id>.log
~/.quirq/scheduler/runs/<job-id>.jsonl
```

Use the path shown in the drawer for your installation. Opening results never
runs the job and does not create an item under **Inbox → Items**.

| Status on the row | Meaning |
| --- | --- |
| **Succeeded** | The command finished with exit code zero. |
| **Failed** | The command returned a nonzero exit code. |
| **Timed out** | The run took longer than the time limit and was stopped. |
| **Command not found** | Its program could not be found. |
| **Could not start** | Space could not launch or finish the command normally. |
| **Interrupted** | A run in progress could not be recovered after a server restart. |
| **Skipped (still running)** | A scheduled run came due while the previous run was still going. |

The results drawer shows the same results with their short codes (`ok`,
`failed`, `timed_out`, `missing_binary`, `error`, `lost`, `skipped`).

## Watch jobs from Inbox

Open **Inbox → Jobs** (`#/inbox/jobs`) to see every saved job, repeating and
one-time. Each row shows the badge, description, schedule and whether it is
enabled, and its latest result with the date and duration.

![Inbox Jobs listing three saved jobs with Run now and Results on each](/images/space/jobs.png)

**Run now** starts the job; **Results** opens the same drawer as in Setup.
**Open Setup** takes you to **Setup → Jobs** to create, edit or delete jobs.
The list updates every 30 seconds, and every three seconds while a job is
running.

## Edit or delete a job

**Edit** reopens the job in the same card, as the choice that produced it, and
lets you switch its kind. Saving an unchanged **Every…** schedule keeps its run
times. **Delete** removes the job after confirmation and keeps its history and
logs on disk. Deleting does not stop a run already in progress.

## Ask an agent to manage jobs

Click **Copy agent prompt**, paste it into your agent, and describe the job you
want. The prompt gives the agent the Space jobs API and your time zone, and asks
it to check for duplicates, set a folder and a time limit, and confirm the next
run time. The card shows the **Create job** address of this Space; the agent
must be able to reach it.

See [Setup → Server](/docs/space/space-walk/setup#restart-the-server) for local
and HTTPS proxy access, and the
[storage guide](/docs/space/observability/storage#saved-commands-and-schedules)
for where job files live.
