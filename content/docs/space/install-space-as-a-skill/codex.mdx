## Choose a skill

After installing the plugin, start a new local task and ask **“Open XO Space.”**
Codex uses the `quirq` skill to discover Space, install it if needed, or start
the existing checkout. A fresh install uses `~/xo-workspace` unless you name
another workspace, and selects the Codex backend.

You can also ask for a skill by name. In Codex CLI, enter `/skills` or type `$`
to select one.

| Skill | Example prompt | Behavior |
|---|---|---|
| `quirq` | Open XO Space. | Discover, install or start as needed, then open the UI. |
| `quirq-status` | Use quirq-status to check my local Space. | Read-only installation, health, URL and workspace inspection. |
| `quirq-install` | Install XO Space in ~/work. | Install once in a durable workspace; reuse a discovered installation. |
| `quirq-start` | Use quirq-start to start my installed Space. | Start the existing checkout without fetching updates or changing its backend. |

The visible plugin name is **XO Space**. The stable plugin ID is
`quirq@quirq-ai`, and the marketplace is displayed as **Quirq**.

## Understand discovery and startup

Discovery reads the install pointer at `~/.config/quirq/install.json` (or under
`XDG_CONFIG_HOME`), probes the recorded port and local ports 5002/5003, then checks
the current directory for a checkout. It does not scan the entire filesystem.

| Status | Meaning |
|---|---|
| `running` | Verify the server and open its reported `/space/` URL. |
| `installed` | The checkout exists; an open/start request starts it. |
| `not_installed` | No installation was found; an open/install request can create one. |

A status request never installs, starts, stops, or updates Space. An explicit
open, run, or install request authorizes the corresponding setup/start steps;
Codex's runtime permission gates still apply.

Manage credentials in [Setup → Secrets](/docs/space/space-walk/setup#manage-credentials)
and external app OAuth connections in [Setup → Connectors](/docs/space/space-walk/connectors).

Startup verifies server health, the checkout, and effective workspace roots.
Existing `.env`, the Python environment, saved backend, and roots are preserved.
Projects and state live outside the plugin cache. Merely opening Space does not
update the server.

## Server lifetime and maintenance

Space runs as a foreground process in a task or terminal owned by the local
Codex session. Keep that process alive. Ask to open Space again after it stops;
the plugin does not create a system service. For an independently managed
terminal, use [Install Space](/docs/space/install-space).

See the app walkthrough for [update and removal](/docs/space/install-space-in-codex#update-or-remove)
and [troubleshooting](/docs/space/install-space-in-codex#troubleshooting).
The current source is the
[XO Space plugin](https://github.com/quirq-ai/xo-space/tree/development/plugins/quirq).

Project creation and the shared todo workflow are covered separately by the
[xo-projects skill](https://github.com/quirq-ai/xo-space/blob/development/.agents/skills/xo-projects/SKILL.md).
