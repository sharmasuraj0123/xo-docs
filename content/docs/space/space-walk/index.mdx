## Find the right tab

The primary tabs are **Projects · Agents · Inbox · Setup**. Press **1–4** to open them in that order. Shortcuts pause while an input, text area, or select has focus.

| Tab | Use it to | Default route after `/space/` |
| --- | --- | --- |
| [Projects](/docs/space/space-walk/files-explorer) | Survey projects, browse files, compare Git history, and manage local projects | `#/projects/overview` |
| [Agents](/docs/space/space-walk/sessions) | Inspect session usage, prompts, trends, and telemetry sources | `#/agents/overview` |
| [Inbox](/docs/space/space-walk/inbox) | Handle incoming items, scheduled jobs, project activity, and sharing | `#/inbox/items` |
| [Setup](/docs/space/space-walk/setup) | Configure the workspace, intelligence layer, connectors, secrets, and server | `#/setup/workspace` |

**Wiki** sits at the top right beside **GitHub**. It opens the local quick start and topic directory at `#/wiki`. **Open docs** within Wiki opens a detailed guide in a new tab; **GitHub** opens the [source repository](https://github.com/quirq-ai/xo-space). Keep the full URL when bookmarking, including any access query parameters your deployment requires.

## Projects: Overview, Data, Timeline, Manage

Opening Space without a hash, clicking **Projects**, or pressing **1** opens **Overview**. The second navigation row contains four sections:

| Section | What it shows | Route |
| --- | --- | --- |
| [Overview](/docs/space/space-walk/dashboard) | The dashboard map, purpose environments, and project todos | `#/projects/overview` |
| [Data → List](/docs/space/space-walk/files-explorer) | Project rows and expandable file browsers | `#/projects/data/list` |
| [Data → Graph](/docs/space/space-walk/graph) | A spatial map of mapped projects and files | `#/projects/data/graph` |
| [Data → Tree](/docs/space/space-walk/tree-lens) | A horizontal folder hierarchy | `#/projects/data/tree` |
| [Timeline](/docs/space/space-walk/timeline) | Git commit days and first appearances of mapped files | `#/projects/timeline` |
| [Manage](/docs/space/space-walk/manage) | Clone projects, inspect metadata and issues, pin, share, and remove local projects | `#/projects/manage` |

**Data** contains the **List | Graph | Tree** switch and remembers the last Data view you visited. **Sharing** lives under [Inbox](/docs/space/space-walk/sharing). An open file preview stays visible while moving within Projects, including Timeline and Manage; leaving Projects closes it.

![Data List with project counts and activity](/images/space/projects-list.png)

Old links such as `#/dashboard`, `#/graph`, `#/tree`, `#/time`, and `#/sessions` still resolve. New bookmarks should use the section routes above; `#/projects` opens Overview.

## Search and quick actions

Click **Press ⌘K to search**, or press **⌘K** on macOS / **Ctrl+K** elsewhere, to open the command menu. Type to find a page, a project by name or description, or an action. Use **↑ / ↓** to choose, **Enter** to open, and **Esc** to close.

![Command palette showing a matching project](/images/space/command-palette.png)

- Choosing a project opens its file drawer in **Projects → Data → List**.
- **Refresh this page** refreshes views that support it. Otherwise use the
  page’s own **Refresh** or **Refresh status** control.
- **New project** opens **Projects → Manage**, where **Add project** starts a clone.
- **Copy link to this page** copies the current URL.

On maps and pages that support search, **/** also opens the command menu. The navbar only shows a page's inline search field when it already has an active query. When that field is visible, the command menu can pass text to **Search “…” on this page**. Clear the field with its clear button or **Esc**. Page queries apply only to that page's loaded content; they are not a workspace-wide file-content search.

## A useful first walkthrough

1. In [Setup → Workspace](/docs/space/space-walk/setup), confirm your projects folder. Review runtime and watcher coverage in **Intelligence layer**.
2. Open [Projects → Manage](/docs/space/space-walk/manage) to clone a repository or inspect a discovered project. Pin projects you visit often.
3. Open **Projects → Data → List**, expand a project, and read a file. Use **Graph**, **Tree**, or **Timeline** for another view of the workspace.
4. Use a project's **View activity** action in Manage to open its todos, open sessions, and watcher events in **Inbox → Activity**.
5. Open [Agents](/docs/space/space-walk/sessions) for recorded usage and prompts. Continue running tasks in your runtime's own client or an API client.
6. Handle incoming items in [Inbox](/docs/space/space-walk/inbox), and configure external app access in [Setup → Connectors](/docs/space/space-walk/connectors).

## Understand empty or unavailable views

A project can have files without Git history, a watched runtime can lack aggregate telemetry, and an authorized connector can have polling disabled. Each guide explains its prerequisites and empty states.

Local project browsing does not require a connector account. Sharing and Connectors use external services and require their own configuration. The UI's bind address and authentication depend on how you run it; see [installation](/docs/space/install-space).

For storage and runtime boundaries, read [Observability](/docs/space/observability) and [Auto-detection](/docs/space/auto-detection). For the separate replay tool, read [Session replay](/docs/space/space-walk/replay).
