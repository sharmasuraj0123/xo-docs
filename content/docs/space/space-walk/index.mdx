## Find the right tab

The top bar contains **Projects · Timeline · Sessions · Inbox · Wiki · Setup · Connectors**. Press **1–7** to open those tabs in that order. Shortcuts pause while an input, text area, or select has focus.

The separate **Docs** and **GitHub** links open the
[Space documentation](https://docs.quirq.ai/docs/space) and
[source repository](https://github.com/quirq-ai/xo-space) in new tabs. They keep
your current Space view open.

| Tab | Use it to | Route after `/space/` |
| --- | --- | --- |
| [Projects](/docs/space/space-walk/files-explorer) | Inspect project files, activity, todos, history, and sharing through five lenses | `#/projects` |
| [Timeline](/docs/space/space-walk/timeline) | Compare git commits and dated files across projects | `#/time` |
| [Sessions](/docs/space/space-walk/sessions) | Review supported runtimes' sessions, usage, and recorded prompts | `#/sessions` |
| [Inbox](/docs/space/space-walk/inbox) | Read incoming items and mark them seen or done | `#/inbox` |
| [Wiki](/docs/space/space-walk/wiki) | Find a quick start, topic summaries and links to detailed guides | `#/wiki` |
| [Setup](/docs/space/space-walk/setup) | Configure roots, runtime, watcher coverage, credentials, and updates | `#/secrets` |
| [Connectors](/docs/space/space-walk/connectors) | Connect apps, control agent actions, and collect items into Inbox | `#/connectors` |

Keep the full URL when bookmarking a view, including any access query parameters your deployment requires.

## One Projects tab, five lenses

Opening `/space/` without a hash starts at **Dashboard**. Clicking **Projects**, or pressing **1**, opens **List**. Choose another lens from the persistent control beneath the top bar; Projects stays highlighted throughout.

| Lens | What it shows | Route |
| --- | --- | --- |
| [Dashboard](/docs/space/space-walk/dashboard) | Project nodes grouped into purpose environments with project todo context | `#/dashboard` |
| [List](/docs/space/space-walk/files-explorer) | Project rows and expandable working details | `#/projects` |
| [Graph](/docs/space/space-walk/graph) | A spatial map of projects and their files | `#/graph` |
| [Tree](/docs/space/space-walk/tree-lens) | Folders and files arranged as a horizontal hierarchy | `#/tree` |
| [Sharing](/docs/space/space-walk/sharing) | Shared projects, incoming repositories, and sync status | `#/sharing` |

![Projects List with project counts and activity](/images/space/projects-list.png)

Opening a supported file brings up a floating preview. It stays open when you move between all five Projects lenses, including its selected historical version, Source mode, size, and position. Leaving Projects closes the preview. See [files and version history](/docs/space/space-walk/files-explorer).

## A useful first walkthrough

1. Start with [Setup](/docs/space/space-walk/setup). Confirm the projects root and watcher coverage point to the folders and runtimes you actually use.
2. Open **Projects → List**, find a project, expand it, and open a file. Review its todos, sessions, and git history when those sources are available.
3. Choose **Dashboard**, **Graph**, or **Tree** for another view of the same workspace. Use **Timeline** when the question is when files or commits changed.
4. Open **Sessions** to inspect recorded usage and prompts for a supported telemetry source. Continue running agent tasks in your runtime's own client or an API client.
5. Open **Inbox** to read new items. Follow **Open** or **Open link** to their context, then mark the inbox item **Done** when handled.
6. If you need external app tools or incoming mail/calendar items, configure **Connectors** and its **Polling** drawer.

## Understand empty or unavailable views

Space combines different sources; they do not all become available at once. A project can have files without a git repository, an active runtime can lack aggregate telemetry, and a connector can be authorized without polling enabled. Each guide explains its prerequisites and empty states.

Local project browsing does not require a connector account. Sharing and Connectors use external services and require their own configuration. The UI is served by the Space backend; its bind address and authentication depend on how you run it. Check [installation](/docs/space/install-space) before exposing a local server remotely.

For storage and runtime boundaries, read [Observability](/docs/space/observability) and [Auto-detection](/docs/space/auto-detection). For the distinction between session inspection and the separate replay tool, read [Session replay](/docs/space/space-walk/replay).
